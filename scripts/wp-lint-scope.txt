# THE BOUNDARY THIS FILE ENCODES ([AGENT], A-TRIP 2026-08-28). The proof
# stack's machine crossing is the Laws/lifting/adequacy layer: the modules
# that derive WP rules from the step relation and export WP conclusions as
# first-order machine sentences. Relative to that layer:
#
#   police <path>    — a file ABOVE the boundary (tier-3 WP proofs).
#                      Text lint: no kernel-decision closures in ANY
#                      spelling (`native_decide`, `decide +kernel`,
#                      `decide +native`, `decide (config := { kernel/
#                      native := true })`) and no unfold-class mention of
#                      the executable machine (`stepFn`/`stepFnIter`/
#                      `execStmt`/`execStmtLoop`/`allStreamsOk`/
#                      `allStreamsOkPool`). Closure check: every theorem/
#                      def/opaque's STATEMENT closure must be machine-free
#                      (V-STMT) and its PROOF/VALUE term may reach the
#                      machine only through boundary modules (V-PROOF);
#                      every module a walk reaches must be positively
#                      classified (V-CLASS — unknown = violation).
#   boundary <path>  — a file OF the boundary layer itself. It
#                      LEGITIMATELY mentions the step relation and the
#                      executable machine (that is its job — it is where
#                      proofs are allowed to cross), so the machine-
#                      mention rules do not apply; the kernel-decision
#                      bans still do. The closure walk STOPS at boundary
#                      THEOREMS only; boundary DEFS are recursed (a def
#                      is kernel-transparent — stopping at defs was the
#                      audited rfl-reduction/TC-decide evasion, fix F3).
#                      Every boundary file is ENUMERATED here one line at
#                      a time — no directory globs (fix F2): enrolling a
#                      boundary file always costs a tracked, diffable
#                      edit of this config.
#   boundary-kernel-ok <path> <count>
#                    — a boundary file additionally carrying GRANDFATHERED
#                      kernel-decision certificates (plan §2d: "the
#                      existing pilot quartets are grandfathered as
#                      labeled scaffolding"). <count> PINS the number of
#                      kernel-decide occurrences (all spellings, comment-
#                      stripped): the lint FAILS if the actual count
#                      drifts either way (fix F6 — the grandfather can
#                      never silently grow). `native` spellings stay
#                      banned. New files never start here.
#   boundary-sentences <path>
#                    — a corpus SENTENCE-EXPORT file (fix-round R2; the
#                      split-file convention below). Its declarations MAY
#                      state first-order machine sentences (no V-STMT),
#                      but their PROOFS are walked with police rules,
#                      with exactly two licenses: (i) constants written
#                      in the theorem's own TYPE are statement vocabulary
#                      and exempt from the forbidden check; (ii) GoCore
#                      constants are name-checked but not recursed (the
#                      statement legitimately embeds the drivers). Text
#                      lint: full police rules (a sentence proof never
#                      needs an unfold or a kernel decision — it routes
#                      through goSpec_of_wp/adequacy, which are boundary
#                      theorems). Documented residual: a proof grinding
#                      strictly within its own statement's written
#                      vocabulary is not distinguishable by constant
#                      reachability; the lint's unfold bans and review
#                      cover that corner, and the expected proof shape is
#                      a two-liner.
#   police-root <dir>
#                    — a COMPLETENESS root (fix F5): every *.lean under
#                      it (recursively) must be classified in this file
#                      as police / boundary / boundary-kernel-ok /
#                      boundary-sentences / exempt-file, or the lint
#                      FAILS naming the stragglers. This is how corpus
#                      enrollment is made mechanical: landing a file
#                      under the root forces a reviewed scope decision in
#                      the same change. A missing or .lean-empty root
#                      FAILS (fail-noisy).
#   exempt-file <path>
#                    — under a police-root but deliberately OUT of the
#                      WP-tier scope (legacy modules policed by their own
#                      gates). Must exist on disk (fail-closed). Never
#                      valid for a NEW file: new files under a root
#                      enroll as police or boundary-sentences.
#   exempt <FQName>  — a per-DECLARATION carve-out for the closure check
#                      (plan §6.3's declared-carve-out clause: the
#                      sanctioned ∃-discharge sites). Inline provenance
#                      comment required; a non-resolving name FAILS.
#                      None today.
#
# THE SPLIT-FILE CONVENTION (published here for corpus workers; R2).
# Every corpus member ships as (at least) two files:
#   1. the WP-walk file — representation predicates, the WP lemmas, loop
#      invariants, the calculus work. Enrolled `police`. Its statements
#      are WP-tier: they never mention the executable machine.
#   2. the sentence-export file — the designated first-order sentences
#      (∀ ch/fuel interpreter-runs-the-pinned-program shapes) plus their
#      thin discharges (a goSpec_of_wp/adequacy application citing the
#      WP-walk file). Enrolled `boundary-sentences`.
# Co-locating sentences with WP walks in one police file fails V-STMT by
# design — split the file. A NEW Laws/lifting file is enrolled
# `boundary` by an explicit line here (deliberate, reviewed); it is
# NEVER auto-classified.
#
# EXIT/FAILURE SEMANTICS (fix F10, both tools): exit 2 = the scope
# itself is unusable (config missing/unreadable, or the police+sentence
# set is EMPTY — whatever the cause, including a root that expanded to
# nothing); exit 1 = violations, or scope problems (missing listed file,
# count drift, completeness stragglers) alongside a nonempty scope.
# Every failure names its cause.
#
# Files listed NOWHERE and under no police-root are outside this gate's
# scope: either BELOW the boundary (GoCore, the language instances'
# machinery, ghost state) or pre-Iris-era proof modules policed by their
# own gates. In the CLOSURE WALK nothing is ever silently skipped: a
# reached module is boundary (stop at theorems), police/sentences/our
# tree (recurse), enumerated upstream (Iris/Std/Init/Lean/Qq/Batteries —
# stop), or a V-CLASS violation (fix F1: unknown-module = fail closed;
# the repo's own non-GoLean-rooted modules — Audit, Challenge, Solution,
# SliceSpike — deliberately fall here if a policed proof ever reaches
# them).
#
# SANCTIONED SIDE-CONDITION KERNEL CERTIFICATES ≠ VENEER (R3): concrete-
# seed side conditions on the checker-reducible well-formedness
# vocabulary — `MachineWf`, `normalizeValueForTy`, `applyStrictOp`,
# `dynamicDispatch?` — are sanctioned discharges (Surface.lean:127-129:
# "at concrete seeds it is discharged by `decide` (the checker is
# kernel-reducible)"). The named list and the veneer/side-condition
# distinction live in scripts/WpVeneerClosure.lean's docstring.
#
