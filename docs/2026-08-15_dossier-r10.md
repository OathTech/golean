# Dossier R10 — abort-line rendering (pinned to gc's `preprintpanics` behavior, fail-closed at unmodelable edges)

G3 register item 16. Inventory §R10; BUG-004 (open, red pins).
Proposal only — batched for user ruling.

## 1. The latitude

The spec does not define abort OUTPUT at all — the `panic: ...` head
lines are pure gc runtime realization. Machine:
`renderPanicHead`/`renderPanicPayload` (Machine.lean:1373–1443)
render gc's exact shapes and FAIL CLOSED where deciding gc's answer
needs machinery the model lacks: eface identity for the
`[recovered]` collapse (allocation identity — unmodeled),
`Error()`/`String()` rewrite (a method call at abort time),
multi-line/non-ASCII payloads (BUG-004 items 1/3/4, open with red
pins).

## 2. Evidence

### SPEC

None — the spec's §Handling panics defines `panic`/`recover`
semantics, not process output. (R12 covers the exit-status half; R9
the message texts of the VALUES themselves.) The upper bound here is
argued purely from gc realization — there is nothing else to argue
from, which is itself the finding: EVERY abort-rendering claim is
implementation-scoped by nature.

### GC probes (`docs/evidence/2026-08-15-dossier-r10/`, verbatim heads)

- `panic(42)` → `panic: 42` — the plain rendering the machine
  models.
- error payload → `panic: custom error text` — gc CALLS `Error()` at
  abort time (`preprintpanics`); the machine fails closed on this
  shape (method call at abort — the honest refusal, re-exhibited).
- recover-then-repanic → `panic: first [recovered]` / `\tpanic:
  second` — the chain shape; its eface-identity variant (same value
  re-panicked) is the other fail-closed edge.

All abort with in-binary exit status 2 (R12's territory, witnessed
in passing).

### Corpus / de-facto spec

Crash-report tooling parses these lines (panic parsers in log
aggregators are a real genre), which pressures gc to keep the format
stable — but no LANGUAGE claim rests on them; the machine needs the
rendering only for the strict lane's abort-output equality.

### XIMPL / ARCH

NOT-OBTAINED. gccgo's abort output differs (local knowledge,
UNVERIFIED). ARCH: `preprintpanics` and the `[recovered]` rendering
have shifted across gc releases (the panic-nil GODEBUG change is the
recent adjacent example — local knowledge, UNVERIFIED).

## 3. Proposed disposition

**KEEP PIN + FAIL-CLOSED EDGES AS-IS; the re-envelope obligation is
BUG-004's existing fix list — no new disposition.** This dossier's
role is to certify the POSTURE, not to move it.

- ARGUMENT: the fail-closed edges are the honest form (visible red,
  never a guessed rendering); the deep blocker (allocation identity
  for eface collapse) is C11-quotient-adjacent and priced there.
  Widening (an output envelope) is meaningless — there is no second
  conforming output to envelope over, only gc's, because the spec
  says nothing.
- COUNTER-ARGUMENT: pinning process OUTPUT at all drags a pure
  runtime artifact into the semantic surface; the strict lane could
  instead compare only panic VALUES (R9) and exit class (R12) and
  drop head-line equality. REBUTTAL: head-line equality is what
  catches rendering-path divergences (BUG-004's reds were found by
  it); dropping it trades a working discriminator for nothing.
- WHAT WOULD CHANGE THE ANSWER: BUG-004's fixes landing (items
  3/4 are mechanical; item 1 waits on identity modeling — the ruling
  may re-prioritize); gc reworking abort output (pins fire).
