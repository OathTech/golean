### F1 — RECORDS-CLAIM (argument precision): the unreachability of the disclosed refusal-class change rests on an invariant that is asserted, not stated

**What.** `arrayIndexNatFormed`'s docstring (`Ops.lean:1471–1491`) and the handoff §2 argue «a store reaches an `.index` step only through an address the machine FORMED under Go's bounds check … and arrays never shrink». For a `storeTarget` chain (`resolveChain` → `indexTargetLoc`, `Machine.lean:245`) that is exact: the plan and the commit run on the SAME store `s` (`deliverV` passes its one `s` to both), so the re-check sees the very array the formation checked. For an ELEMENT RUN (`Mem.storeElems` at `.index base (offset + start + i)`, `Ops.lean:2852`) and for a store through a slice-derived pointer (`sliceIndexLoc`, `Ops.lean:570`, which checks `i < slice.len` against the HEADER, never the backing) the argument needs one more fact: **every slice header satisfies `offset + cap ≤ |backing array|`**. No `StateWf` conjunct states it; no theorem proves it. It holds BY CONSTRUCTION: (i) every header-formation site bounds `cap` by the real array — `sliceFromArray` by `values.size` (`Ops.lean:607–626`), `sliceFromSlice` by the source `cap` (`:585–605`), `makeSlice` allocates exactly `cap` cells (`Machine.lean:1367–1368` over `buildDefaultArrayValue cap`), the append spill allocates exactly `newCap` (`buildAppendBackingValue`, `Ops.lean:2996`, pads to `newCap`, refuses if longer), the in-place append keeps `cap` (`Machine.lean:1630`), `[]byte`/`[]rune` set `cap = len = |array|` (`Machine.lean:440/713`), nil headers are `0/0/0` (`Ops.lean:2068/2118`); (ii) an array cell never resizes because a whole-value store normalizes at the cell's declared `.array n` type and the normalizer REFUSES a length mismatch (`Ops.lean:1181`), and `Store.alloc` normalizes at birth (`:1251`); (iii) the only header-rebasing conversions are refused by name (`(*[N]T)(s)` `unsupported`, `Ops.lean:2056`; `[N]T(s)`'s succeeding form likewise); (iv) the wire carries slice EXPRESSIONS, not raw headers (`NativeToIR.lean:546–553`). I checked each site (`static-checks-and-statement-diffs.txt` lists them) and probed the surrounding programs (§2). The argument is sound; it is not written down where the refusal is, and it is not a theorem.
**Why it matters.** The claim «a path no well-formed run reaches» is the whole justification for turning a Go panic into `.internal`; a future header-forming site (a `reflect`/`unsafe` frontier, a slice-to-array-pointer implementation, a wire change) would silently make it reachable, and nothing mechanical would say so.
**Disposition proposed [AGENT].** Records-class fix: name the invariant and the formation-site list in `arrayIndexNatFormed`'s docstring (or the memory-module docstring) as «by construction, unproved»; open a small follow-up (C4 or the next hygiene slice of this module) to state `∀ header reachable, offset + cap ≤ |backing|` as a `StateWf` conjunct with `writeAt_noPanic_of_readAt_ok` as its consumer.
