### The example

**Go** (`Corpus/coverage/exec/examples/histogram/main.go`): `histogram`
builds a `map[uint64]uint64` of counts over a `[]uint64`, reads the
count of a queried key (`counts[q]` — Go's zero value on an absent
key), then counts the map's entries with a VARIABLE-FREE
`for range counts {}`. Harness `histogram_harness_r(n, seed, q)` is the
S3 RELATIONAL style: setup family `v[i] = seed + i%3`, a copy loop into
a fixed-cap `[8]uint64`, then `histogram(v, q)` — the values AND both
summaries returned as data.

- **JC (observable choice):** both summaries returned, not one — the
  queried count exercises the map INDEX READ and `distinct` exercises
  the enveloped `for range`. The charter asked that the observable
  range over the map so the `∀ch` teaching point is real; `distinct`
  does, and its spec (`distinctCount`) is a function of the returned
  values alone. Principle: the harness ruling (returned data over a
  verdict) + the charter's order-invariance requirement.
- **JC (variable-free range):** `for range counts {}` rather than
  wordcount's `for _, c := range counts`. It is the honest lowering of
  "count the entries", and it makes the machine side markedly cheaper —
  `bindIterVars` with no binders allocates NOTHING, so the range loop is
  state-stable. Principle: velocity, where honesty is unaffected (the
  Go is what a Go programmer would write).
