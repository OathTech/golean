## Unit G4.4 — the comparator-judge worktree fix (this commit)

Taken FIRST because it is the only item with no dependency on the
proofs build, so it lands while the lane's first full build runs.

- STATUS: **done**. Charter §G4 item 4 / audit follow-up 7.

### The defect, exactly

`scripts/comparator-judge`'s §3c Challenge import-closure walk built
each module's file path and then applied `f="${f//.//}.lean"` — a
dots-to-slashes substitution over the WHOLE path, `$CHECK_ROOT`
included. Any repo root containing a dot is corrupted by it. Path
arithmetic, measured in this worktree:

```
m = GoLeanProofs.Specs.Statements
CHECK_ROOT = /home/dev/projects/golean/.claude/worktrees/gc-debt

BEFORE f = /home/dev/projects/golean//claude/worktrees/gc-debt/proofs/GoLeanProofs/Specs/Statements.lean
AFTER  f = /home/dev/projects/golean/.claude/worktrees/gc-debt/proofs/GoLeanProofs/Specs/Statements.lean
```

`.claude` → `/claude`; the file does not exist; the walk returns
`MISSING:GoLeanProofs.Specs.Statements`, which routes to
`fail "Challenge import closure names missing module …"` — a
fail-CLOSED abort reporting a module that is present and correct. This
is what forced the phase-2 landmark (`8101b726`) to run from a
dot-free clone.

### The fix — FLAGGED FOR THE ARC-END AUDIT (gate-honesty dimension)

**This is a gate edit.** The charter names it the campaign's SOLE
sanctioned one (§HARD BOUNDARIES). It changes 4 lines of logic plus a
4-line comment, all inside `closure_walk`; nothing else in the file
changes. The substitution now runs on the MODULE-DERIVED string only —
`scripts/ci`'s own closure walk is the model (`mf="proofs/$(echo "$m" |
tr '.' '/').lean"`, `scripts/ci:245`).

```diff
 closure_walk() {
-  local queue=("$@") m f
+  local queue=("$@") m f rel
   declare -A seen
   while ((${#queue[@]})); do
     m="${queue[0]}"; queue=("${queue[@]:1}")
@@
     case "$m" in
       Iris*) echo "IRIS:$m"; return 0 ;;
       Std|Std.*|Init|Init.*|Lean|Lean.*|Batteries|Batteries.*|Qq|Qq.*) continue ;;
-      GoLean.*) f="$CHECK_ROOT/GoLean/${m#GoLean.}" ;;
-      GoLeanProofs|GoLeanProofs.*) f="$CHECK_ROOT/proofs/GoLeanProofs/${m#GoLeanProofs.}"; [ "$m" = GoLeanProofs ] && f="$CHECK_ROOT/proofs/GoLeanProofs" ;;
+      GoLean.*) rel="GoLean/${m#GoLean.}" ;;
+      GoLeanProofs|GoLeanProofs.*) rel="proofs/GoLeanProofs/${m#GoLeanProofs.}"; [ "$m" = GoLeanProofs ] && rel="proofs/GoLeanProofs" ;;
       *) echo "UNKNOWN:$m"; return 0 ;;
     esac
-    f="${f//.//}.lean"
+    # Dots -> slashes on the MODULE-DERIVED part ONLY (scripts/ci's walk is the
+    # model). The old form substituted over the whole path, so any CHECK_ROOT
+    # containing a dot — every .claude/worktrees/<lane> — turned into a fake
+    # "missing module" fail-closed abort (recorded 2026-08-02, fixed 2026-08-15).
+    f="$CHECK_ROOT/${rel//.//}.lean"
     [ -f "$f" ] || { echo "MISSING:$m"; return 0; }
```

**What did NOT change, deliberately:** the `Iris*` / stdlib / UNKNOWN
arms and their fail-closed verdicts, the tolerant comment-stripped
import extraction (`scripts/lean-scan.sh`), the trust-tool pin checks,
the fresh-clone default, the axiom allowlist. No gate was weakened: the
walk's every failure verdict is byte-identical, and the fix makes MORE
of the closure reachable to be checked, never less. Trust tools
(`deps/comparator`, `lean4export`, `landrun`) untouched and unrun.

### The invisible-dependency check (the audit's warning class)

The audit said to re-confirm that `StmtOps` declares no simp/instance/
macro before relying on its absence. **It does not hold as stated**, and
two further channels turned up. Recorded because each one could have
produced a silent behaviour change rather than a build error:

1. **`Laws/StmtOps.lean` DOES extend two attribute tables** —
   `@[go_walk_simp]` (3 lemmas) and `@[go_walk_law]` (3), consumed by
   `Tactics/GoWalk.lean`'s `go_walk`. Harmless HERE only because a
   check showed **no shard in scope uses `go_walk`** — but the audit's
   flat "declares no simp/instance/macro" is wrong and should not be
   re-used by the next reader.
2. **`derive_entry_eq` is EntryEq `syntax`**, invisible to every
   name-level scan. Used by `WC/HarnessSetup`, `WC/HarnessR`,
   `IS/Setup`; `EntryEq` is pinned into those three headers explicitly.
3. **`open … GoLean.Surface` is load-bearing**: `FuelMeasure`,
   `StepKit` and `EntryEq` all declare INTO `GoLean.Surface`, so a
   bare `harness_readout_of_total` resolves only through that `open`.
   Dropping the last supplier from a shard makes the `open` itself an
   `unknown namespace` error — which is exactly what the first build
   attempt hit (`WC/Pure`), and how it was found.

### Method

`artifacts/g4/usage.py` (gitignored scratch) resolves every identifier
in each shard the way Lean does — bare names only through `open`ed or
enclosing namespaces, dotted tokens at their longest declared prefix —
and attributes it to a declaring module. Two earlier methods were tried
and are recorded because they are traps:

- **olean/environment scan (rejected).** Iterating `moduleData` and
  reading `ConstantInfo.value?` sees NO theorem proofs: Lean 4.31 does
  not materialise theorem values on import (probe: `HarnessSetup`, 53
  constants, 30 with values, all 23 theorems without — `getConstInfo`
  does not force them either). It reported `Laws.StmtOps` used by ZERO
  modules repo-wide while four shards name it in a proof. Any import
  analysis built on it is a silent under-count.
- **naive token grep (rejected).** Counts `.ok` / `Except.ok` as uses
  of `GoLean.Frame.ExSim.ok`, and misses `wordCountLowered.funcs` as a
  use of `wordCountLowered`.

**The build remains the confirming check** — notation, macros and
attribute-table extensions are invisible to any name scan.

### Criterion applied

Every surviving import is a module some name in that shard resolves to,
or supplies a macro/namespace it needs. Transitive implication is NOT
used to drop an import (e.g. `Frame.Transfer` reaching `Frame.Sim`):
explicit direct dependencies are the stable, reviewable form, and a
list that depends on a THIRD module's imports is not a minimal list,
just a fragile one.
- JC: dead `open` lines were pruned together with the imports that
  supplied them (12 lines across 9 shards) — an import cannot be
  dropped while a dead `open` pins its namespace, so this is part of
  the item, not scope creep. Every one is confirmed dead by the build:
  Lean rejects `open` of an absent namespace and every unresolved name.
- JC: `WC/HarnessR` goes UP, 2 → 10 imports. It previously imported the
  `WordCount` root and inherited everything; its real dependencies are
  now explicit. The root import stays for now and is what G4.2 replaces.
