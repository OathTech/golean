## 1. Status and grade vocabulary

One PRIMARY status per row; cross-references (`→ FR-n`, `→ Q-*`,
`L:<ref>`) carry partiality without leaving anything grey. The frontier
table (§4) is the authority for every red case in the baseline.

- **covered(G)** — green corpus evidence, sufficiency GRADED:
  - **A** — green here IMPLIES the section is covered: all three layers
    of the sufficiency strategy (`docs/native-frontend-goal.md`) are
    present — isolated cases, edge enumeration, and an
    effect/order-OBSERVING integration witness. (The slice-1 archetype
    is the bar: a green row that cannot observe order does not count
    toward A.)
  - **B** — enumerated, with NAMED gap(s) — each gap is listed inline
    or as a §7 TODO row. Green is strong evidence, not an implication.
  - **C** — TOUCHED: existence-level green only; sufficiency not
    argued. Do not cite a C row as support beyond "the construct runs".
  - **D** — DELEGATED: the section is static semantics enforced by
    go/parser + go/types UPSTREAM of both the oracle and the machine
    (the corpus is type-checked Go; both sides read the same checked
    program), so a differential divergence on it is structurally
    impossible; rejection behavior is pinned by the negative compile
    lane where cited. The S3-audit caveat is a D-caveat: constant-heavy
    greens attest go/constant folding, not GoCore arithmetic.
- **frontier(FR-n)** — the feature is unsupported; the FR row carries
  the refusal point (file:line + error string as in the source), spec
  anchors, scope estimate, sequential-vs-concurrency call, and queue
  position or design question. Every frontier case is a VISIBLE
  feature-blocked red — enumerated red, never absent grey.
- **latitude(ref)** — the section's delta from gc is a spec-open point
  held per the latitude inventory / divergence ledger entry cited.
- **out-of-language** — justified ROW BY ROW (§2's notes); never a
  convenience bucket. Marker reds keep such boundaries visible where
  they can be probed at all.
