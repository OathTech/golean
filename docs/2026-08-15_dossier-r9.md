# Dossier R9 — run-time panic values and message texts (pinned to gc's realized strings)

G3 register item 15. Inventory §R9 (register extension #8). Proposal
only — batched for user ruling.

## 1. The latitude

The spec mandates WHICH conditions panic and that the values are
`runtime.Error`s, but leaves the exact error values unspecified. The
machine pins gc's exact texts everywhere (index/slice bounds
Ops.lean:92–218, map-key hash phrasings Ops.lean:1613–1636, make-
negative strings Machine.lean:685–722, channel op panics
Machine.lean:1966–2012, nil-payload `*runtime.PanicNilError`
Machine.lean:1323, the `$runtime.Error` box vs plain-string box
distinction — BUG-054).

## 2. Evidence

### SPEC (go1.26.5, §Run-time panics)

> "Execution errors such as attempting to index an array out of
> bounds trigger a run-time panic equivalent to a call of the
> built-in function panic with a value of the implementation-defined
> interface type runtime.Error. That type satisfies the predeclared
> interface type error. The exact error values that represent
> distinct run-time error conditions are unspecified."

### GC probe sheet (`docs/evidence/2026-08-15-dossier-r9/`, verbatim)

13 classes with box class + exact text (README lists all). Two
structural facts the sheet witnesses beyond raw strings:

- BOX CLASSES: every runtime condition (including `panic(nil)`'s
  `*runtime.PanicNilError`) is a `runtime.Error`; sync-package misuse
  panics are PLAIN STRINGS — observable via `recover().(string)`,
  the BUG-054 distinction the machine models.
- NON-UNIFORM PREFIXES: `runtime error: ` appears on some classes
  (index, slice, deref, div, makeslice) and not others (nil map
  write, makechan, close/send channel trio) — the pin must track
  per-class strings; no uniform rule exists to compress it.

### Corpus / de-facto spec

Deployed code DOES observe panic messages — log pipelines, test
assertions (`assert.PanicsWithValue`), recover-and-classify
middleware. That pressure pins gc's texts as de-facto constants
(and indeed gc changes them extremely rarely, each time breaking
test suites — the "with length" additions were release-noted;
local knowledge, UNVERIFIED). The de-facto argument here supports
the PIN, not an envelope: the ecosystem treats the strings as
stable.

### XIMPL / ARCH

NOT-OBTAINED. gccgo's texts differ in several classes (local
knowledge, UNVERIFIED) — the datum that would size a real envelope
if one were ever wanted. ARCH: `runtime.Error` as the mandated TYPE
dates to Go 1; message texts have never been specified.

## 3. Proposed disposition

**PERMANENT-PIN with the standing caveat: no claim about panic
MESSAGE CONTENT transfers beyond gc-at-the-pinned-version.** The
equality lane exists BECAUSE of this pin (the inventory's own
framing) — dissolving it into message-identity envelopes would
destroy the strict lane's decisive signal for near-zero verification
value.

- ARGUMENT: message identity is the differential's sharpest
  discriminator (it caught BUG-054's box distinction, E11's check
  orders, R8's wrap). The pin is version-tracked by the corpus; a
  toolchain bump that reworded a message fires reds immediately.
  The honest cost — the transfer caveat — is already standing
  doctrine (register #8).
- COUNTER-ARGUMENT: theorems mentioning panic messages are thereby
  gc-scoped, and a portable-semantics flag should not have
  gc strings in its semantic core. REBUTTAL: the CONDITIONS are
  spec-forced and portable; only the rendered strings are pinned,
  and headline theorems already avoid message vocabulary (the
  statement-TCB rules keep observations at termination/values). The
  strings live at the observation boundary, which is exactly where
  a one-implementation pin belongs.
- WHAT WOULD CHANGE THE ANSWER: a cross-implementation equality
  lane (then per-class message SETS become necessary); a claim
  consumer needing panic-message portability (none exists).

## 4. Evidence gaps

- XIMPL (gccgo texts): NOT-OBTAINED; marked UNVERIFIED.
- The probe sheet covers 13 of the machine's pinned classes; the
  map-key hash phrasings and abort-time renderings are exercised
