## 1. The latitude

`sort.Slice` is documented NOT stable — the permutation among equal
elements is implementation latitude (DOCS class). The machine's
`sortSlice` (Syntax.lean:248–253 / Ops.lean:1931–1947) is an
insertion sort — deterministic and, being an insertion sort, stable —
with the site-recorded argument: "exact for integers, where Go's
instability is unobservable".

## 2. Evidence

### DOCS (sort package)

> "The sort is not guaranteed to be stable: equal elements may be
> reversed from their original order."

(sort.Slice's documentation; sort.SliceStable exists precisely
because Slice reserves this latitude.)

### GC probe (`docs/evidence/2026-08-15-dossier-r13/`, verbatim)

64 records, 4 key classes: `equal-key inversions after sort.Slice:
30` — instability REALIZED by gc's pdqsort (not just documented);
`SliceStable inversions: 0` as contrast. So the latitude is live: a
struct-sorting program can observe gc outside any stable-sort
singleton.

### The declared-unobservable argument (verified in form)

The machine supports int-kind element sorts. Two `==`-equal ints are
bit-identical — no observation can distinguish which "equal 5" came
first, so EVERY permutation among equals yields identical observable
states, and the stable insertion sort is a quotient-style
representative of all conforming sorts ON THAT DOMAIN. The argument
is scoped AT THE SITE to int kinds — the scoping is what makes it
sound, and the probe shows exactly what breaks when the scope is left
(struct elements: 30 observable inversions).

## 3. Proposed disposition

**KEEP the declared-unobservable narrowing, scoped to int kinds at
the site; the entry RE-OPENS the day non-integer sorts land** (the
site's own text, affirmed) — and when it re-opens, the shape to reach
for is a PERMUTATION ENVELOPE over equal-element orders (E9's
map-permutation mold), not a pin to pdqsort's realized permutation
(compiler-internal-equivalent: version-fragile and shape-dependent).

- ARGUMENT: on the supported domain the narrowing is not a narrowing
  at all (observationally) — it is the C11-quotient pattern in
  miniature, argued informally at the site. Nothing to widen today.
- COUNTER-ARGUMENT: the informal argument could be promoted to a
  small theorem (equal-int-permutation invariance) per the (q) class.
  REBUTTAL: worth it only when a second sort kind lands; recorded as
  the re-open path's first step rather than done now.
- WHAT WOULD CHANGE THE ANSWER: non-integer sort support (re-opens
  the entry, disposition pre-argued above); a float sort (equal keys
  distinguishable via ±0/NaN payload — the scoped argument fails
  there in a sharper way, noted for the re-open).
