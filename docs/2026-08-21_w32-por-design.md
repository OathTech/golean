## 0. THE BINDING DESIGN CONSTRAINT (Mike, 2026-08-20 — recorded before any building)

Verbatim in substance: **"the top level claims need to be over the
*slow but obviously correct* execution semantics."** The theorem shape
that satisfies it: for every program,

    observations_optimized(p) = observations_slow(p)

— **SET EQUALITY, not per-result iff. COMPLETENESS is the dangerous
direction**: an optimizer that silently prunes a branch it wrongly
believed redundant SHRINKS the set — a false confluence certificate.
The equality is proven in Lean over the slow semantics; running the
optimized enumerator then licenses conclusions about the slow one.
The in-repo template is the Sym evaluator: the optimized machinery
stays OUTSIDE the statement TCB (refusal-class fail-closed shapes +
the deletion test), a refinement/equivalence theorem lands into the
naive enumeration, and top-level statements never mention the
optimized machinery.

## 1. The slow semantics, as a definition (the spec this slice adds)

The naive enumeration today lives in CLI code (`poolDFS`/`poolStepDFS`,
`GoLean/CLI.lean` — `partial`, cap-guarded, accountant-mirrored). It is
not a statement-grade definition. The spec this slice adds is smaller
than any enumerator — it is the ∃-image of the UNMODIFIED interpreter
driver over all choice streams and all fuels
(`GoLean/GoCore/EnumSpec.lean`):

    inductive Obs where                     -- the observation vocabulary
      | ok (values : List GoValue)          -- main .normal + readout
      | panic (msg : String)                -- any goroutine's abort
      | race                                -- the detector's refusal

    def obsOf? (resultLocs : List Loc) :
        Except GoError (ExecOutcome × Choices) → Option Obs
      | .ok (.normal σf, _) =>
          match loadMany σf resultLocs with
          | .ok vs => some (.ok vs)
          | .error _ => none
      | .error (.panic msg) => some (.panic msg)
      | .error .raceDetected => some .race
      | _ => none                           -- fuel-out, deadlock, stuck,
                                            -- non-normal outcomes: not
                                            -- observations

    /-- THE SLOW SEMANTICS: the machine's reachable observation set —
    every stream, every fuel, `execProgLoop` itself. -/
    def SlowObs (resultLocs : List Loc) (m₀ : MultiConfig)
        (r₀ : RaceState) (o : Obs) : Prop :=
      ∃ fuel ch, obsOf? resultLocs (execProgLoop fuel m₀ r₀ ch) = some o

Properties that make this the right spec, argued:

- **Obviously correct.** Its only non-trivial constituent is
  `execProgLoop` — the interpreter driver every differential run and
  every pool theorem already rests on. `obsOf?` is a 6-line projection.
  Nothing here is enumeration machinery.
- **It IS the records' meaning.** A membership row's certified set has
  always meant "the distinct observations over the whole choice tree"
  (CLI docstring); the ∃-fuel form makes "terminating members" literal
  — a divergent branch has no fuel at which it observes, so the wedge
  family's `nonterm`-counted branches are excluded by the SPEC, not by
  a counting convention. A deadlocked or stuck stream yields no
  observation (and the checker below REFUSES deadlock-reachable
  graphs, preserving the fail-loud claim standard — the spec-level
  exclusion is never a license to skip them silently).
- **Statuses match the lane's**: ok/panic/race are exactly
  `enumPoolRun`'s member statuses; `.race` is `raceUpdate`'s refusal
  propagating through the driver.

The certified records' claims restate over `SlowObs` with NO change in
substance: "certified set S" means `∀ o, o ∈ S ↔ SlowObs locs m₀ r₀ o`.
(Wording change, flagged: the old records' claims were stated over the
CLI tree — "the enumerated tree's distinct observations", trusted via
the accountant + sentinel + alias-ladder guards. The restatement is
over the interpreter itself; for rows certified by the new engine the
guards are REPLACED by the theorem in §3. Rows still certified by the
DFS engine keep the old trust story unchanged.)

## 2. The reduction chosen — state-identity dedup (a certified quotient), not sleep sets / source-DPOR / mover-POR — and why, from this machine's shape

**The blowup is path-multiplicity over a small state graph.** B1/B2
widen the BOUNDARY COUNT per goroutine segment (a consult at every op
completion and loop re-entry). Two goroutines with n and m boundaries
interleave in ~C(n+m, n) schedules; B1 roughly doubled n and m, which
squared the tree (stage-C log: 1.2M → >400M for request-reply). But
the underlying STATE space is the grid — positions × heap variants —
which B1/B2 did NOT grow at all (no new configurations beyond the
marker, no new heap shapes). The five rows' trees are 10²–10⁵-fold
path-redundant over their state graphs. The DFS's prefix-sharing
cannot see this: two pick-prefixes that CONVERGE to the same
`(MultiConfig, RaceState)` are distinct tree nodes forever.

**Why dedup over the named POR families, argued from the machine:**

1. **Completeness is structural, not argued.** Sleep sets, source-DPOR
   and mover-POR all prune SCHEDULES whose equivalence rests on an
   independence relation (disjoint footprints ⇒ commutation). Proving
   commutation of `stepThread i`/`stepThread j` requires frame lemmas
   over the whole of `stepFn` (a footprint soundness theory the repo
   does not have; audit Q11's stamps are adjacent but unbuilt).
   State-identity dedup prunes only subtrees rooted at LITERALLY
   IDENTICAL states — the pruned subtree is not argued equivalent, it
   IS the retained one. The dangerous direction of the binding
   constraint (a wrongly-pruned non-commuting branch) cannot arise:
   there is no independence judgment to be wrong about.
2. **The proof assets exist.** The per-node exhaustiveness the
   equivalence needs ("every stream's step from this node lands in the
   enumerated successor set") is exactly the ∀-streams checker's
   architecture: `stepThread_oblivious` + `stepAllBranchesOk_sound`
   (MultiStreams.lean) already prove it for the oblivious shapes; the
   L4-waiter extension is one new lemma in the same mold. No new
   semantic theory.
3. **It composes with the principled POR later.** NPDRF/slice 5's
   mover theorem, when it lands, multiplies this reduction (fewer
   states explored, and per-state fewer branches). Nothing here
   forecloses it; the certificate checker's per-node branch
   enumeration is exactly where an ample-set restriction would slot,
   with its own completeness lemma.
4. **It fits the rows.** The five rows are terminating,
   finite-state, high-interleaving programs — the exact profile where
   dedup wins and where footprint-POR alone (without dedup) would
   still leave C(n+m,n)-shaped redundancy between INDEPENDENT segment
   reorderings that reconverge.

Judgment, logged: audit Q11 (entry-identity stamps) is NOT consumed —
dedup needs no footprint/mover lemmas at all; Q11 stays slice-4-routed.

## 3. The architecture: untrusted engine, certificate, verified checker

The Sym mold, sharpened by the comparator-judge mold: the OPTIMIZED
machinery produces a CERTIFICATE; a small TOTAL checker validates it;
the theorem is about the checker alone.

- **The engine** (`GoLean/EnumDedup.lean` — `partial` allowed, outside
  the semantic core, deletable): worklist search over nodes
  `(MultiConfig × RaceState)`, dedup via the compiled hash/BEq
  (UNTRUSTED — a hash collision or BEq lie can at worst make the
  checker refuse or the cert list duplicates; never a wrong accepted
  set). Emits `DedupCert`:
  - `nodes : Array Node` — the closed graph (root at index 0),
  - `succ : Array (Array Nat)` — per node, per enumerated branch
    vector (in the CHECKER's own enumeration order), the successor's
    index — the engine's dedup knowledge, handed over as hints so the
    checker never needs a map,
  - `members : Array (Obs × Choices × Nat)` — the observation set,
    each with a realizing stream + fuel (witnesses).
- **The checker** (`GoLean/GoCore/EnumDedupCheck.lean` — total,
  fail-closed, in the lib beside the metatheory): validates
  1. `nodes[0]` is the seeded root (sound eqb against `(m₀, r₀)`);
  2. per node: the terminal classification mirrors `execProgLoop`'s
     arms — panic ⇒ its `Obs` ∈ members; main-normal ⇒ readout `Obs` ∈
     members (+ at the L5 window, ALSO the continue branch below);
     deadlock / non-normal outcomes / empty pool ⇒ REFUSE;
  3. per node, per branch vector `vec` of the node's certified shape
     class (§4): the REAL `stepMulti m vec` must return
     `.ok (m', [], ev)` (leftover exactly empty), then
     `raceUpdate … ev …` either `.ok r'` — whereupon
     `(m', r') eqb nodes[succ-hint]` (sound eqb ⇒ propositional
     equality) — or `.error .raceDetected` — whereupon
     `.race ∈ members`; any other error REFUSES;
  4. per member: replay `execProgLoop fuel m₀ r₀ witness` and check
     `obsOf?` yields exactly that member (soundness by construction).
- **Sound equality** (`GoLean/GoCore/StateEqb.lean`): the nested
  inductives (`Ty`, `GoValue`, `Expr`, `Stmt`, `Cont`, `Config`)
  cannot derive `DecidableEq` (verified empirically — "no deriving
  handlers applied"), and their derived `BEq`s are the documented
  opaque-partial stubs. This slice adds fuel-structural `eqb`s in
  `GoValue.eqbFuel`'s exact mold with ONE-DIRECTIONAL soundness
  theorems (`eqb a b = true → a = b`, by functional induction — the
  false catch-all makes off-diagonal cases vacuous). Completeness of
  `eqb` is NOT needed: an eqb too weak (fuel exhaustion) makes the
  checker refuse — fail closed, never unsound.

**TCB accounting.** The top-level statement mentions: `SlowObs`
(= `execProgLoop` + `obsOf?`), `Obs`, `checkCert`, and the certificate
value. The checker is BELOW the theorem (verified, not trusted); the
engine appears nowhere in any statement and its deletion leaves the
lib + proofs building (the deletion test, §7). What a consumer must
understand to read a certified-row claim: `SlowObs` — six lines over
the interpreter. Runtime trust is the same compiled-code class as
every differential artifact (the theorem is about the logical
functions; `scripts/ci` exercises the compiled ones — unchanged from
the existing lane's trust story, minus the accountant/sentinel/ladder
heuristics the theorem retires for dedup-certified rows).

## 4. The theorem and its proof shape

    theorem checkCert_slowObs
        {resultLocs : List Loc} {m₀ : MultiConfig} {r₀ : RaceState}
        {cert : DedupCert}
        (hc : checkCert resultLocs m₀ r₀ cert = true) :
        ∀ o, o ∈ cert.obsSet ↔ SlowObs resultLocs m₀ r₀ o

(set equality as membership-iff; `cert.obsSet` = the members'
observations). Two directions:

- **Soundness (⊆, the easy direction):** each member's witness replay
  is literally an `execProgLoop` equation the checker evaluated;
  `∃ fuel ch` introduces it.
- **Completeness (⊇, the dangerous direction):** strong induction on
  `fuel`, generalized over nodes: *if `(m, r)` is an entry of
  `cert.nodes` and `obsOf? (execProgLoop fuel m r ch) = some o`, then
  `o ∈ cert.obsSet`.* Unfold one driver layer: the terminal arms are
  the checker's per-node requirements; the step arms need THE
  NORMALIZATION LEMMA — for a node of certified shape class, every
  stream-successful `stepMulti m ch = .ok (m', ch', ev)` is realized
  by one of the checker's enumerated vectors with the SAME `(m', ev)`
  and empty leftover. Then `raceUpdate` (a function of `(m, ev, m',
  r)`) agrees, so the run either enters `nodes[succ-hint]` — equal to
  `(m', r')` by eqb-soundness, recurse at `fuel − 1` — or refuses with
  `.race ∈ members`. Streams on which `stepMulti` ERRORS contribute no
  observation (`obsOf?` is `none` on every propagated error but
  panic/race, and step errors are never those) — vacuous.

**The certified shape classes (the fragment), v1:**

- **N-OBL** — boundary or non-boundary node whose stepping target(s)
  satisfy `poolThreadOblivious`: vectors = the scheduling slot alone
  (`[pick]` at menu ≥ 2, `[]` otherwise). Exhaustiveness is
  `stepThread_oblivious` (exists) + the `consumeAtE` peel
  (`stepAllBranchesOk_sound`'s own steps, extracted).
- **N-L4** — target at a single-arrival multi-candidate pairing
  (`arrivalCases = .ok (.single bc cs)`, `cs.length ≥ 2`): vectors =
  scheduling slot ++ `[p]`, `p < cs.length`. Exhaustiveness is the NEW
  lemma `stepThread_l4_pick` (the one-pick analogue of
  `stepThread_oblivious`, same unfolding walk, `consumeAtE_of_lt`
  normalizing the pick mod the bound).
- **N-APP** (added during the slice, google-search's diagnosed
  refusal) — a NON-spilling `appendSlice` apply: stream-oblivious by
  `stepFn_append_nospill`; the genuine spill branch still refuses.
- **Everything else REFUSES** (fail closed, the Sym quit mold): L2
  `.multi` arrivals, consuming (multi-ready) selects, `mapIterK`
  picks, genuine append spills, `$pkginit`-bearing programs. A row needing a
  refused shape stays on the DFS engine with its existing trust story
  — the partial reduction with the TOTAL proof, per the brief.

Expected coverage of BUG-065's five at v1: google-search (buffered
sends/recvs — cellPath), rwmutex-order (sync ops — cellPath), sb-chan
(select-with-default — `.done`-shaped, the slice-4 refinement's
class), request-reply (paired ops, single candidates) under N-OBL;
worker-pool/sum plausibly needs N-L4 (multiple parked workers on one
jobs channel). Verified empirically at re-certification; any row the
fragment refuses is recorded honestly, never forced.

**Back edges and divergence come free, recorded:** backEdge consults
are ordinary menu consults to the checker (no per-site cap needed —
the graph is finite where the STATE space is finite, loop counters
included), and CYCLES in the certified graph are sound — the
completeness induction is on fuel, not on graph acyclicity, and a
divergent stream simply observes nothing. The wedge-family rows
(`send-then-spin`, spin states cycling in place) are therefore
candidates for exhaustive-equivalent dedup certificates with no
`nonterm` counting — an upgrade recorded as follow-through, not
claimed until run.

## 6. Cost surface and staging (each stage lands gate-green)

- **P0 (this note).**

  Docs: records' meaning restated (§1). No behavior change.
- **P2 — sound equality:** `StateEqb.lean` — eqb tower + soundness
  for `Ty`/`GoValue` (defs exist, proofs new) and `Expr`/`Stmt`/
  `Cont`/`Config`/`HeapCell`/`ExecState`/`RaceState`(+components)/

  `deriving DecidableEq` where the handler applies). Mechanical;
  the largest single item (~58+40 constructor walks).
- **P3 — checker + theorem:** `EnumDedupCheck.lean` (defs) +
  `EnumDedupSound.lean` (`stepThread_l4_pick`, the normalization
  lemma, `checkCert_slowObs`). The driver induction cribs
  `execProgLoop_ok_of_allStreamsOkPool`; the peel cribs

- **P4 — engine + CLI:** `EnumDedup.lean` + `coverage-observations
  --engine dedup` (default remains the DFS; the flag is per-row

## 7. Walker refusal + deletion test (the Sym pattern, this module's form)

- **Refusal class:** the checker's shape flags (§4) — every
  non-certified consumption shape refuses in the checker AND the
  engine surfaces the refusal reason; no silent fallback between
  engines (a row DECLARES `engine=dedup`; a refusal is a red row,
  never a quiet DFS rerun).
- **Deletion test, RUN at P4:** deleting `GoLean/EnumDedup.lean` (the
  engine) leaves the library, the checker, the theorem, and the
  proofs' default build green — only the CLI target's `--engine dedup`
  mode fails to build, which is the intended dependency direction
  (CLI → engine → checker → GoCore; never GoCore/proofs → engine).
- The statement-TCB gate's list is unchanged: `checkCert_slowObs` is
  metatheory over base definitions (`execProgLoop`, `obsOf?`) — no
  Iris, no Sym, no engine in the statement.

## 8. Residuals, named

- The v1 fragment refuses L2-`.multi`, consuming selects, `mapIterK`,
  append spills, `$pkginit` — extension is per-shape lemmas in the
  N-L4 mold, priced only when a row needs one.
- The engine's dedup hash/BEq is a performance surface only; a
  degenerate hash degrades to the DFS cost profile, loudly (work cap).
- RaceState is IN the node identity (verdict-correctness by
  construction); if clock growth defeats state convergence on some
  row, the certificate grows and the work cap fails loud — the row
  then waits for the mover lane (recorded, not laundered).
- The slice-5 mover/NPDRF theorem composes: ample-set restriction of
  the checker's per-node vectors, with its own completeness lemma,
  over the same certificate shape.
