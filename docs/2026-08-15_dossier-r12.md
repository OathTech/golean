# Dossier R12 — exit codes and terminal classification (pinned at the harness boundary)

G3 register item 18. Inventory §R12 ("rides with R9/R11; no machine
content beyond the terminal classes themselves"). Borderline-IN
judgment (g3.md): harness-level but a distinct pin. Deliberately a
short dossier. Proposal only — batched for user ruling.

## 1. The latitude

The spec says nothing about process exit codes. gc realizes: 0 normal,
2 for unrecovered panic / deadlock / fatal throw, `os.Exit(n)`
passthrough, 66 for a `-race` report (TSan's default). The
differential HARNESS keys its `expected_status` dispatch on these
(scripts/diff-coverage); the machine's content is only the terminal
CLASSES (ok / panic / deadlock / fatal / raceDetected), not numbers.

## 2. Evidence

### SPEC

§Program execution ends at "the program exits. It does not wait for
other (non-main) goroutines to complete." No exit-code text exists
anywhere in the spec. DOCS: `os.Exit` documents its argument as the
status code; the race detector's exit code is documented as
configurable via `GORACE=exitcode` (default 66).

### GC probes (`docs/evidence/2026-08-15-dossier-r12/`, verbatim)

    exit-ok: exit 0
    exit-explicit: exit 7
    exit-panic: exit 2
    exit-race (-race): exit 66
    exit-deadlock: exit 2

All five classes realized as the harness assumes; the deadlock probe
also witnesses C9's `fatal error: all goroutines are asleep -
deadlock!` head (the exit CLASS is this dossier's scope; C9 itself is
out of the register — concurrency).

### Corpus / de-facto spec

Exit code 2 for panics is load-bearing across the ecosystem (CI
systems, process supervisors, test harnesses distinguish crash from
failure); GORACE's default 66 is relied on by race-CI scripts.
De-facto pressure is strong and gc-stable.

### XIMPL / ARCH

NOT-OBTAINED. gccgo also exits 2 on panic (local knowledge,
UNVERIFIED).

## 3. Proposed disposition

**PERMANENT-PIN at the harness boundary, riding R9/R11's caveat.**
No machine change is even expressible — the machine has terminal
classes, not exit integers; the pin lives entirely in
`scripts/diff-coverage`'s dispatch, where it belongs.

- ARGUMENT: the harness must key on SOMETHING; gc's codes are stable,
  documented (os.Exit, GORACE), and de-facto pinned. An "envelope"
  here would mean accepting any exit code — i.e., not checking — a
  strict weakening of the oracle. The terminal-class abstraction in
  the machine is already the portable half.
- COUNTER-ARGUMENT: none of substance found; the only exposure is a
  future gc changing a code (release-note-level event; the whole
  corpus would go red at once, unmissable).
- WHAT WOULD CHANGE THE ANSWER: a second-implementation lane whose
  codes differ (the harness dispatch grows a per-oracle table —
  mechanical).

## 4. Evidence gaps

- XIMPL: NOT-OBTAINED. GORACE=exitcode override not probed
  (documented knob; the default is the harness-relevant datum and is
  probed).
