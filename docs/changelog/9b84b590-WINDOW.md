| core/wide-value-1127 | **The wide operators' VALUE forms — each targeted operator without its final store, and the equation tying the machine's operator to it; contract 477 → 479** (raft-proofs' request of 2026-11-27, approved by the [USER] the same day with the equations contracted; backlog row 64). NO CHANGE to the interpreter: `applyStmtOp`, `applyStmtOp.plan`, `applyStmtOpCore.plan` and `stepFn` are untouched, and nothing the machine runs is new — every differential and negative row unchanged (the gate's check). NEW, beside them (`GoLean/GoCore/WideValue.lean`): `StmtOp.hasValueForm` (the seven operators that store a computed value into a target: `allocNew`, `makeSlice`, `makeMap`, `makeChan`, `copySlice`, `appendSlice`, `randIntn`); `applyStmtOpValue.plan` / `applyStmtOpValue` — the same validation on the operands MINUS the target, a commit that performs the operator's own writes (the backing or payload allocation, the in-place element writes) and returns the value the machine would store into the target, with the store after those writes, the stream, the picks and the trace; `storeValue` / `storeValueInto` — the store left out. CONTRACTED (family `widevalue`): `applyStmtOp_plan_eq_value : op.hasValueForm = true → applyStmtOp.plan ctx s choices op nt (.addr loc :: vs) = storeValueInto ctx loc <$> applyStmtOpValue.plan ctx s choices op nt vs` and `applyStmtOp_eq_value : … → applyStmtOp ctx s choices op nt (.addr loc :: vs) = applyStmtOpValue ctx s choices op nt vs >>= storeValue ctx loc`. WHAT THE EQUATIONS DO NOT SAY: they are stated at a target that IS an address (the machine checks its target with `valueAsLoc` at a per-arm position; a nil target is the nil-dereference panic); the value is the OPERAND of the final `Mem.store`, which normalizes at the target cell's declared type and can refuse; the operators with no target (`mapAssign`, `mapDelete`, `clearMap`, `clearSlice`, `sortSlice`, `print`) have no value form and `applyStmtOpValue.plan` refuses them by name; `randIntn` WITHOUT a target has the same operand list as the targeted form minus its target, so the value form does not refuse it — it makes the machine's draw (same stream, same pick record) and returns the pick — and the equation relates the targeted machine form only; the stores that are not a wide operator's (a channel receive's or select's targets, a try-lock's result, an atomic's, a call's results) deliver through `enterRecvTargets` / the `tgtOpK` spine / `storeTarget` with the value explicit in the configuration and are outside this; the comma-ok forms are `applyRhsOp`'s, already value-returning; the equations are at the plan and at the composed apply, not through `runCommit` (a consumer's step equations take the composed `applyStmtOp … = …` as their premise). The value forms' arms are the machine's arms with the target operand and the last store removed; an edit to one side alone fails the build at the equation. |
