| core/wide-value-1127 | **The wide operators' VALUE-FORM SURFACE — each targeted operator without its final store, the equations tying the machine's operator to it, and what holds of the value forms standing alone; contract 477 → 524** (raft-proofs' request of 2026-11-27, approved by the [USER] the same day, then widened on the [USER]'s direction that this be a principled surface others might target; backlog row 64). NO CHANGE to the interpreter: `applyStmtOp`, `applyStmtOp.plan`, `applyStmtOpCore.plan` and `stepFn` are untouched, and nothing the machine runs is new — every differential and negative row unchanged (the gate's check). DEFINITIONS, beside them (`GoLean/GoCore/WideValue.lean`): `StmtOp.hasValueForm` (the seven operators that store a computed value into a target: `allocNew`, `makeSlice`, `makeMap`, `makeChan`, `copySlice`, `appendSlice`, `randIntn`); `applyStmtOpValue.plan` / `applyStmtOpValue` — the same validation on the operands MINUS the target, a commit that performs the operator's own writes and returns the value the machine would store into the target, with the store after those writes, the stream, the picks and the trace; `storeValue` / `storeValueInto` — the store left out; `dropValue`; and (`WideValueFacts.lean`) `StmtOp.valueShape`, `wideWrittenRoot?`, `WideEffect`, `CommitEffect`. CONTRACTED, 47 statements (family `widevalue`; the [USER] approved contracting the equations and directed the surface, the list of further statements is the lane's): (1) THE EQUATIONS — `applyStmtOp_plan_eq_value : op.hasValueForm = true → applyStmtOp.plan ctx s choices op nt (.addr loc :: vs) = storeValueInto ctx loc <$> applyStmtOpValue.plan ctx s choices op nt vs`, `applyStmtOp_eq_value : … → applyStmtOp ctx s choices op nt (.addr loc :: vs) = applyStmtOpValue ctx s choices op nt vs >>= storeValue ctx loc`, `applyStmtOp_plan_randIntn_untargeted` (the untargeted machine form is the value form with the value dropped), `applyStmtOpValue_plan_of_not_hasValueForm` (an operator with no target has no value form: refused by name), `applyStmtOp_randIntn_untargeted` (its un-split form), `stmtPlan_targets` (the machine's classification of a wide statement, `stmtPlan`, yields a target count of 0 or 1; at 1 the operator has a value form and the operand list is non-empty; at 0 with a value form the operator is `randIntn` on one operand — so a consumer reads its case off `stmtPlan`'s answer; the theorem speaks of that answer, not of the statement's syntax); (2) SUCCESS — `applyStmtOpValue_plan_error_iff`, `applyStmtOpValue_plan_ok_iff`, `applyStmtOp_plan_target` (a machine apply that succeeds had an address for its target), `applyStmtOp_plan_ok_iff_value` (the machine's plan succeeds exactly when the target is an address and the value plan succeeds; `randIntn` in its two-operand form), `applyStmtOp_plan_error_of_target` (a target that is not an address never succeeds); (3) THE VALUE FORMS' OWN INVARIANTS — `applyStmtOpValue_commit_noPanic`, `applyStmtOpValue_plan_tame`, `applyStmtOpValue_commit_tame`, `applyStmtOpValue.plan_noDead`, `applyStmtOpValue_noDead`, `applyStmtOpValue_plan_effect`, `applyStmtOpValue_effect` and each of its clauses as its own statement — `applyStmtOpValue_shape` (the value has the operator's constructor), `_size` (the heap grew by at most one cell), `_frame` (every existing root cell but the backing the operator may write is as it was), `_frame_of_growth` (if the heap grew, NO existing cell was written: a spilling `appendSlice` leaves its old backing alone), `_wf` (`StateWf` is kept and the value is bounded by the allocator) — the five `valueShape_*_normal` lemmas (constructor facts: the value is normal at any unnamed pointer / slice / map / channel type), the stream statements `applyStmtOpValue_no_draw` (every form but `appendSlice` and `randIntn` returns the stream untouched, no picks), `_appendSlice_stream` (in place: nothing drawn; spilling: one `appendSpill` consult), `_randIntn` (the exact result), `TableMono.applyStmtOpValue_plan_eq`, `TableMono.applyStmtOpValue_eq`, `TableMono.storeValue_eq` (agreement under table slices); (4) THE MEMORY FRAME LAWS — `Store.updateCell_frame`, `storeLoc_frame`, `Mem.store_frame`, `Mem.storeElems_frame`, `Mem.storeRun_frame` (a write changes no root cell but its own, and no size), `Store.alloc_frame`, `Store.allocCell_frame` (an allocation changes no existing cell); (5) THE STEP — `stmtOpOut_of_hasValueForm`, `retV_stmtOpK_apply_value`, `retV_stmtOpK_apply_value_panic`, `retV_stmtOpK_apply_value_error`, `retV_stmtOpK_apply_value_store_error`, `retV_stmtOpK_apply_randIntn_untargeted` (`stepFn` at the apply position in terms of the value form and the store; not tagged `@[stepFn_eqns]`). WHAT IS NOT SAID: the equations with a target are stated at a target that IS an address (`applyStmtOp_plan_target` says a successful apply had one; a nil target is the nil-dereference panic, at a per-arm position the value form does not have); the value is the OPERAND of the final `Mem.store`, which normalizes at the target cell's declared type and can refuse; WHICH stop a non-address target gives is not stated, and when the target is the only operand (`makeMap`/`makeChan` with no hint or capacity) the value form on `[]` succeeds where the machine stops — that step is the machine's own equation; the exact value and store of each operator are not stated, `randIntn` excepted (the effect gives the constructor, the frame and the bounds — not that `allocNew`'s value is the address `s.heap.size`, nor what a `copySlice` or in-place `appendSlice` leaves inside the backing it writes), nor that an `int` result is in range for its kind, nor anything at a named type by the `valueShape_*_normal` lemmas; the trace a value form returns and the width of a spill's consult are not stated; the machine-side theorems this rests on (`applyStmtOp_plan_tame`, `applyStmtOp_commit_noPanic`, `applyStmtOp_wf`, `Mem.store_noPanic`, the consumption theorems) are not in the contract; the stores that are not a wide operator's (a channel receive's or select's targets, a try-lock's result, an atomic's, a call's results) are outside this, their value already explicit in the configuration; the comma-ok forms are `applyRhsOp`'s, already value-returning. The value forms' arms are the machine's arms with the target operand and the last store removed; an edit to one side alone fails the build at the equation. |
