# Boolean runtime invariant and safety

This increment implements the runtime part of O1 in the
[approved charter](2026-09-05_typed-consumer-sprint-charter.md), using the
separately named stronger admission from the
[static typing increment](2026-09-05_boolean-typing-design.md). The old A3a
admission and its deliberately accepted unbound counterexample are unchanged.
The runtime interpreter, relation and frontend are unchanged.

## Structural contract

`BooleanRuntime.Inv context results s c` has five fields:

1. `SameContext context s`: all non-heap execution context fields agree.
2. `BoolHeap s`: every allocated cell is a root Boolean cell at Boolean type.
3. Every externally pinned result location denotes such a cell.
4. `TypedControl s c`: the current computation and every saved continuation
   have the required Boolean/address sorts, actual name lookups, and valid
   environments.
5. `MachineWf s c`: the existing structural location and iterator checks.

None is defined by reachability, future safe execution, or evaluator success.
The actual initial setup theorem must establish all five fields. In particular,
`MachineWf` is a proof obligation for setup, not an ambient assumption that
execution will succeed. `initial_control` bridges a `FunctionTyped` body and
the environment facts supplied by setup to the actual empty entry barrier.

`EnvRoots` covers **every stored binding**, including hidden outer bindings.
`Covers Γ env` says every name bound in the static context has an actual
successful lookup. The two facts are independent: existence of a visible
lookup alone does not exclude a hidden dangling binding.

## Sequences, initialization and saved environments

`ControlStmt`/`ControlStmts` are structural runtime judgments derived from the
stronger static judgments. They retain Boolean operators, bound reads and
writes, sequential declaration effects, and initialization placement. They
erase freshness and distinct-key checks already performed by admission.

`execSeq` types the head and tail jointly. The tail is checked under the
head's **post-context**, while the current environment need only cover the
head's **pre-context**. Thus a subsequent read can be typed before the preceding
initialization has allocated its cell. The constructor contains the actual
same environment in the current configuration and governing `.seq` frame.
Root initialization and foreign-environment initialization cannot obtain this
constructor.

Nested `seqn` exports declaration effects. `seqCont` may splice two lists
when their saved environments agree. Its proof combines the contexts of the
two lists and weakens the tail through the head's declarations. A block pushes
and allocates a local environment, preserving the enclosing saved environment.

The runtime context abstraction deliberately proves **Boolean memory type
safety**, not lexical binding identity or value equivalence. Since every cell
has the same type, adding a name cannot change the type of a successful lookup.
This union/weakening argument must not be copied unchanged into the mixed-type
recovery profile: heterogeneous shadowing needs a relation to the actual
resolved binding and its type. Source declaration/initializer scope and legal
shadowing remain obligations of static admission and native lowering; the
runtime theorem does not replace the existing native shadowing witness.

## Continuations and memory changes

`ReturnCont` terminates at the driver's actual
`.frame [] [] [] [] .stop`. Its result-location field is empty; the real result
locations remain external pins. `ReturnCont` has no `.stop` constructor, so
return-to-stop cannot be typed. `.next .stop` has a distinct terminal control
constructor.

`BoolCont` types Boolean operators, branches and assignment RHS frames.
`AddrCont` types the address computation generated by a simple assignment.
The remaining control constructors track the store and return transitions.
Their saved environments and pending root locations are included explicitly.

`Extension s t` records a Boolean heap, unchanged non-heap context and a
nondecreasing allocation count. This transports all old root and environment
**types**, including pinned results and saved continuations. It makes no claim
that old Boolean **values** are unchanged. Actual allocation and store success
are proved from the heap cells, using `BooleanStore`; they are not extra
future-success premises.

## Theorems and quantifiers

| API | Contract |
| --- | --- |
| `Inv.progress` | Current configuration is `.next .stop`, or has a relational successor. |
| `control_advances` | Terminal, or actual `stepFn` succeeds for **every** choice stream with that stream unchanged, preserving structural control and heap facts. |
| `control_step` / `Inv.step` | Preservation for **every supplied relational `Step`**, including continuations. |
| `Inv.steps` / `Inv.iter` | Preservation through arbitrary relational traces or successful executable prefixes. |
| `Inv.run_ok_or_fuelOut` | For every fuel and choice stream, actual `runConfig` succeeds or reports precisely fuel exhaustion. |
| `Inv.run_no_refusal` | The terminal-checking driver cannot report a model refusal. |
| `Inv.run_readout` | After normal `runConfig` completion, actual `loadMany` succeeds with Boolean values and the pinned result arity. |
| `Inv.run_choices` | A completed run returns its input choice stream unchanged. |
| `Inv.reachable_silent` | Every reachable configuration has `printOut? = none`. |

`control_step` first applies the existing `step_complete` to an arbitrary
relational successor, obtaining a realizing choice stream. Uniform executable
preservation then applies at that stream. Thus the proof does not confuse
preservation of a chosen successor with preservation of all permitted ones.
`Inv.step` also invokes existing `Step.preserves_wf`.

The bounded safety theorem instantiates existing
`execStmtLoop_ok_or_fuelOut` with **derived** reachable progress.
`runConfig_eq_loop` proves equality of the two existing terminal-checking
drivers, connecting this result to the driver's actual `runProgramM` path.
Raw `stepFn` at `.next .stop` itself refuses; no unconditional raw-step
no-error theorem is claimed.

No sufficient-fuel assumption or general termination theorem is introduced.
Fuel exhaustion is not normal termination. The Boolean profile makes no
platform-dependent numeric or slice allocation requests; the current root
allocator is modeled by finite Lean arrays without an explicit memory quota.
These results concern that existing allocation model, not a claim about
unbounded physical memory. Future bounded root allocation would change the
helper/progress obligations and must be exposed in the profile's resource
contract.

`run_readout` is a type/arity theorem. Functional equations for result values,
program termination witnesses and Iris ownership are separate consumer
obligations. A `loadMany` equation is not a source equivalence theorem.

## Validation boundary

`Tests.BooleanInvariant` contains arbitrary-name staged declaration tests,
an actual structural initial invariant, every-successor and every-fuel
no-refusal families, and negative controls for foreign initialization frames,
root initialization, return-to-stop, wrong result sort, dangling roots and
hidden dangling bindings. Kernel evaluations of the actual
`runConfig`/`loadMany` path test both input values for zero initialization and
restoration of an outer binding after a block changes an inner shadow.

`scripts/check-boolean-runtime` records source hashes, builds the supporting
modules and tests, freshly elaborates their sources, then runs a separate
post-import audit. The audit includes every declaration from
every imported local `GoLean`/`Tests` module, including unused and private
declarations. Three separately compiled poison controls challenge an unused
private axiom in preservation, a private axiom appended to the audit module,
and a trailing `sorry` theorem in the test module. Only the standard classical
trio is allowed. The ordinary CI script includes this gate.

The parent integration owns exact generic `runProgramSetupM` binding/value
identities and their composition with this invariant and the public facade.
This increment alone is not a declaration that all O1 or the larger sprint is
complete. Runtime evidence and the final source-bound review are recorded
with the implementation commit.
