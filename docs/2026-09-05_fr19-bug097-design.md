## §0 The one rule

**Identity is the wire key; display is gc's rendering. They are
different functions of the same type, and the wire carries both.**

    identity(T)  — TypeId.key: injective over Go type identity
                   (spec#Type_identity), qualified by IMPORT PATH,
                   scope-disambiguated for function-local types,
                   structural for anonymous interfaces. The machine
                   decides EVERYTHING by this key and by nothing else.
    display(T)   — gc's runtime type string (`NameString()`, below):
                   qualified by PACKAGE NAME, no scope information,
                   deliberately ambiguous. The machine RENDERS panic
                   texts from this and decides nothing by it.

Before this lane the two were one string (`TypeId.key`, rendered
verbatim by `goTypeNameForMessage`), which is why BUG-059 (path where gc
prints name), BUG-097 (name where identity needs path) and FR-19 (no
scope in the key at all) are one defect seen from three sides: no single
string can be both path-injective and byte-equal to gc's ambiguous text
(identity note §3 said so; this is the structural fix it deferred).

## §1 What gc actually prints (verified at go1.26.5)

The runtime type string — the `<dyn>` / `<target>` in every
`interface conversion:` panic, `%T`, `reflect.Type.String()` — is
`reflectdata.dcommontype`'s `t.NameString()` = `tconv(t, 0,
fmtTypeIDName)` (`reflectdata/reflect.go:480`, `types/fmt.go:239`). Its
own doc: «qualifies identifiers by package name, so it has collisions
when different packages share the same names and identifiers. It also
does not distinguish function-scope defined types from package-scoped
defined types or from each other.» Rules of `tconv2` in that mode, each
confirmed by a probe line in `gc-probes.txt`:

| shape | gc display | probe |
| --- | --- | --- |
| declared type `T` in package with name `n` | `n.T` (`main.T`, `inner.T`, `fmt.Stringer`) — the `·N` suffix of a function-local type is TRIMMED (`SplitVargenSuffix`) | P1 `named->named`, `%T local: main.L`; P2 |
| universe `error` | `error`; `any`/`byte`/`rune` collapse to `interface {}`/`uint8`/`int32` | P4 `main.Pair[interface {},error]`, `uint8 int32` |

| anonymous interface | `interface {}`; else `interface { m1; m2 }` — one space after `{`, `; ` between, ` }` — methods in `CompareSyms` order (exported first by name; then unexported by name, then by package path), an unexported method qualified by package NAME (`main.get() int`), signature without `func`: `(T, U) R` / `(T) (R, S)` / `(...E)`, embedded interfaces FLATTENED | P1 `named->anon-order` (`A(); Z()`), `anon-unexported` (`M(); main.get() int`), `anon-with-embedded` (`Error() string; Get() int`); P2 `inner.get() int` |

Two facts the probes settled that the plan in BUG-097 did not know:

1. **`types.TypeString` cannot be the anonymous-interface key even with
   `pkgQualifier`** (P3): go/types never qualifies unexported interface
   METHOD names, so `interface{ get() int }` from `red/inner` and from
   `blue/inner` — DISTINCT types (spec#Type_identity: unexported method
   names from different packages are different) — would still fuse.
   The key needs its own renderer (§2.2).
2. **gc's local-type counter is a per-package compiler counter** (P4:
   `main.box[main.score·1] main.box[main.other·2] main.box[main.score·3]`
   — `writer.go:1013`, `decl.gen`), trimmed from the type's own display
   but KEPT inside instantiation brackets (`LinkString`). So a
   function-local type as a type argument of a generic TYPE has an
   observable name that depends on `decl.gen` — C6 (ledger §5.1 item 1)
   stands for exactly that shape and no other (§2.4).

## §2 The identity key (frontend; `tools/nativefrontend/identity.go`, `mono.go`, `wire.go`)

### 2.1 Grammar

    TypeId.key := <path> "." <Name> [ "·" <ordinal> ] [ "[" targs "]" ]   declared type
                | "interface{" methods "}"                                 anonymous non-empty interface
                | "struct{}" | "any" | <opaque basic> | "$poisoned" | "$runtime.Error"   canonical / synthetic
    methods    := method ( ";" method )*      in gc's CompareSyms order
    method     := ( <Name> | <path> "." <name> ) "(" [ ktype ("," ktype)* ] ")" [ " " ktype | " (" ktype ("," ktype)* ")" ]
                  — the last parameter of a variadic method is spelled "..." ktype
    ktype      := canonical basic | <TypeId.key of a declared type>
                | "*" ktype | "[]" ktype | "[" N "]" ktype | "map[" ktype "]" ktype
                | "chan " ktype | "chan<- " ktype | "<-chan " ktype
                | "func(" ... ")" ...  (renderSignatureArg's spelling)
                | "interface{" methods "}" | "interface {}" | "struct {}"   (the empty forms keep renderTypeArg's admitted spelling)

Refused (cause named) inside a key: an anonymous NON-EMPTY struct
(FR-13's row — the machine has no `Ty` for it), an unsubstituted type
parameter, a tuple, `unsafe.Pointer`/complex basics (FR-25). Import
paths containing `.` (the separator) or `·` (the scope marker) refuse at
`checkKeyPathGrammar` — `·` U+00B7 is category Po, legal in an import
path by spec#Import_declarations, never in an identifier.

Injectivity, extending identity note §1: `·` and `[` cannot occur in a
Go identifier, so `<path>.<Name>` / `·<ordinal>` / `[targs]` parse
uniquely; two declared types give one key only if same path, same name,
same scope ordinal, same instantiation — i.e. the same declaration at
the same instantiation, which IS Go identity. An anonymous interface key
is a canonical spelling of its method set (names + package path for
unexported names + parameter/result identity keys, gc-ordered), which is
exactly spec#Type_identity's interface rule; the key space is disjoint
from declared keys (`interface{` is not `<path>.`). Belt and suspenders:
`registerMangledKey`/`noteInterface`'s `types.Identical` conflict guards
stay, and emitProgram's duplicate-TypeId refusal stays as the boundary
collision check (now a cannot-happen guard for legal Go).

### 2.2 Function-local types — the FR-19 scope rule

`<ordinal>` is the 1-based index of the local type DECLARATION in its
package's source order (files in the loader's order — lexical filename
order, the spec's presentation order — positions ascending), over EVERY
function-local `type` declaration of the unit (function bodies, nested
blocks, function literals, generic function bodies alike). Computed once
per unit from `types.Info.Defs` (`localTypeOrdinals`), consulted by
`qualifiedTypeName` for any `TypeName` whose `Parent()` is not the
package scope; a local type missing from the table refuses (never a
bare key). Uniform — EVERY local type carries its ordinal, including a
unique one — so a key never changes because an unrelated same-named
local appears elsewhere later… it changes only when an earlier local
declaration is added, which is the same stability class as any
program-derived artifact (the raft twin pin is re-derived when the
subject changes; §5).

Consequences by shape (the FR-19 census, each pinned by a corpus row):

| shape | before | now |
| --- | --- | --- |
| two functions each `type T int` (`noodler/local-types/distinct`) | duplicate-TypeId WHOLE-EXPORT kill | `main.T·1` / `main.T·2`; display `main.T` both; a failed cross-assert prints gc's `main.T, not main.T (types from different scopes)` (`scoping/local-type-identity/scopes-panic`) |
| local type shadowing a package-level one (`noodler/local-types/shadow`) | same kill | `main.Shadowed` (package) vs `main.Shadowed·1` (local); same display |

| local type inside a generic function (BUG-018) | `main.box[int]` | `main.box·N[int]` — display `main.box[int]` (gc, P4 `main.inner[int]`), reflect `Name()` `box[int]` (`TypeId.unqualified` strips the qualifier AND the `·N`). `mono.go renderTypeArg` therefore takes a context: `localTypes:
ordinalKey` for function instantiations (`instFuncId`) and for
anonymous-interface keys; `localTypes: refuse` (C6, text unchanged so
`tools/lowerdiag/causes.tsv`'s `local-type-type-argument` row still
classifies it) for type instantiations (`instTypeId`) — which is also
what a nested instantiation inside a function-instantiation key hits,
correctly: `f[box[score]]` mentions a TypeId that reaches the wire.

### 2.3 Anonymous interfaces — the BUG-097 rule

`emitType`'s `*types.Interface` arm and `ifaceWireName`'s structural
fallback both call ONE constructor, `anonIfaceKey` (identity.go), which
renders §2.1's `interface{…}` form: method names with the declaring
package PATH for unexported ones, parameter/result types through the
same key renderer as §2.2 (local types by ordinal, declared types by
path, instantiations by `instTypeId`). Registered in `seenInterfaces`
under that key exactly as before; `noteInterface`'s BUG-095 conflict
guard is unchanged and — pinned by `multipkg/same-name-anon-iface`
flipping PASS — no longer fires on two same-named packages' interfaces,
because their keys differ (`interface{Get() red/inner.T}` vs
`interface{Get() blue/inner.T}`).

### 2.5 Found on the way: unexported method names (BUG-098, FR-31)

Probe P3 showed `types.TypeString` never qualifies unexported interface
METHOD names; P5 showed gc keeps them package-scoped (`ri.IsGet(x),
bi.IsGet(x)` = `true false`; text `inner.T is not interface { inner.get()
int }: missing method get`). The key of §2.3 qualifies them — but the
wire's requirement lists (`MethodSig.name`), method tables
(`MethodInfo.name`) and dispatch anchors carry BARE names, and the
machine matches by them: with red's and blue's `interface{ get() int }`
now two keys, the machine answers `true true` — a wrong answer where
main REFUSED (the fused key tripped BUG-095's conflict guard). Measured
first on `multipkg/unexported-method-scope/distinct` (differential red,
`true true` vs gc `true false`) before the guard.

Decision [AGENT]: FAIL CLOSED, whole export, by name —
`checkUnexportedMethodScopes` (identity.go) refuses when an unexported
requirement name declared in source package P has a concrete method of
that name declared in a DIFFERENT source package Q (the only shape the
bare-name tables can answer wrong; single-package programs never trip
it; a promoted method keeps its declaring package). `tools/lowerdiag`
gets the static twin (`unexported-method-scope`, FR-31). The proper fix
— path-qualified unexported method names at every method-entry `name`
site, FuncIds unchanged, bare name in the `missing method` text — is
frontend-wide and mechanical; it is ROWED (FR-31, BUG-098) rather than
done here because it touches `emit.go` at many sites while two parallel
lanes edit that file. Cost, measured: the cedar-go census (§6) trades
the two `nodeJSONAlias` kills for the `x/exp/schema/ast` kill (`isType`
required by `x/exp/schema/resolved`, implemented in `ast`) — a package
the census had counted as lowering while the wire could have answered a
satisfaction question about it wrong.

## §3 Display (wire → decoder → machine)

### 3.1 Choice: a display record per TypeDef, not a parser in Lean

Two ways to put gc's text in the machine's panic messages: (a) carry a
`display` string per TypeId on the wire; (b) reconstruct it in Lean from
the key (`red/inner.T` → `inner.T`). (b) needs a path→package-NAME table
anyway (a package's name is not its last path segment in general), a
parser of §2.1 inside the semantic core (interface keys nest arbitrary
types), and gc's `CompareSyms` reordering of unexported methods — a
second implementation of gc's formatter, in the trusted core, with a
key grammar as its input contract. (a) is a total lookup, layout-free,
and puts the ONE implementation of gc's formatter (`gcTypeString`,
frontend) beside the code that already mirrors gc's spellings
(`renderTypeArg`). The machine's rendering stays what AGENTS.md wants:
no frontend name-mangling assumption as a semantic fact — the machine
never inspects a key's shape. Chosen: (a).

Wire (`golean-native-v1`, `program.types[i]`): two REQUIRED fields
beside `name`/`def`:

    {"name": "<TypeId.key>", "def": {...},
     "display": "<gc NameString>",   "pkg": "<declaring import path, "" for unnamed/universe/synthetic>"}

`NativeToIR.decodeTypeDef` refuses an entry lacking either (an old wire
or a forgetting emitter refuses at decode, not at the first panic —
the `methodSets` precedent). The decoder's synthesized `struct{}` entry
carries `display "struct {}"`, `pkg ""`. `Program.typeDisplays : Array
(TypeId × TypeDisplay)` (`TypeDisplay = {name, pkg}`), threaded into
`ExecState.typeDisplays` by both state constructors (`CLI.lean`,
`StepFn.lean`); default `#[]` for hand-built programs.

Frontend: one registry `e.typeDisplays` (key → {display, pkg}) filled
at the minting boundaries — `qualifiedTypeName` (declared, D5 imported,
universe), `instTypeId` (display = name-qualified origin + `[` + the
same rendered args + `]`, which is gc's `LinkString` bracket for the
admitted surface: path-qualified, dot-free paths being their own
`PathToPrefix`), `anonIfaceKey` (display = `gcTypeString(iface)`),
the opaque-basic and `$poisoned` markers (display = key). emitProgram's
last pass attaches `display`/`pkg` to every TypeDef and REFUSES a
TypeDef whose key has no registry entry (a key minted outside the
boundary constructors is a defect, named).

`gcTypeString` (identity.go) implements §1's table for
`fmtTypeIDName`; it is display-only (never a key), so it needs no
injectivity, and it refuses (type parameter outside an instantiation,
tuple) rather than guess.

### 3.2 Renderers in the machine (`GoLean/GoCore/Ops.lean`, `Machine.lean`, `Value.lean`)

* `goTypeNameForMessageFuel`: `.defined id` / `.interface id` (non-empty)
  → the display record; the empty interface keeps its `interface {}`
  special case. NO record → the visible marker
  `<TypeId KEY has no display record>` — never the key (rendering the
  key would be exactly the fail-open BUG-059 texts this design
  retires), never a guess. Reachable only from hand-built programs (the
  decoder guarantees a record per TypeDef); the `Tests/` states that
  render defined-type texts now declare their display records.
* `typeAssertPanicMessage`, concrete-target arm: when
  `display(dyn) == display(target)` (the arm is reached only when the
  types DIFFER, so equal displays mean gc's ambiguity), append
  ` (types from different packages)` if the two `pkg`s differ, else
  ` (types from different scopes)` — `runtime/error.go` verbatim. The
  `pkg` of a non-TypeId `Ty` (pointer, slice, …) is `""`, as gc's
  `pkgpath()` of an unnamed type.
* `renderPanicPayload`'s `main.T(v)` arm renders the display
  (`printanycustomtype` prints the type string).
* `TypeId.unqualified` (reflect `Name()` channel) strips the leading
  qualifier AND the `·N` suffix, keeps `[targs]`; an `interface{…}` key
  yields `""` (an unnamed type's `Name()`).
* `dynamicTypeName?` (Ops.lean) — key-rendering, and unused since the
  message-fidelity work — deleted rather than converted.

### 3.3 What this closes and what it leaves, by name

* BUG-059 CLOSES: `multipkg/same-name-identity-panic` renders
  `interface conversion: interface {} is inner.T, not inner.T (types
  from different packages)` byte-exact.
* Checked for a remainder in the OBSERVATION channel (`CLI.lean`
  `typeName` = `TypeId.unqualified`, the reflect `Name()` contract) —
  and there is none: probe P5 shows gc's `%T` of `Pair[ri.T]` is
  `main.Pair[red/inner.T]` and `Name()` keeps the bracket verbatim, so
  a type instantiation's KEY (mono.go's LinkString spelling) is its
  display and `unqualified` is exact. BUG-059 closes with nothing left
  by name; the one residue this design does NOT address is the C6
  shape (§2.4), which is a refusal, not a text.

## §7 Decisions log

* [AGENT] display carried on the wire per TypeDef (§3.1), not
  reconstructed in Lean — argued above; reversible (the key grammar is
  documented) if a downstream consumer ever needs a key→display function.
* [AGENT] uniform `·N` ordinal on every function-local type (§2.2),
  per-package source order — not "only when ambiguous" (a key that
  depends on the ABSENCE of another declaration is fragile) and not gc's
  `decl.gen` (a compiler counter; we never claim it).
* [AGENT] function-instantiation FuncIds admit local type arguments
  (§2.2) — inside the recorded FR-19 plan (ledger row, 2026-09-04: «the
  same scope-qualified KEY is the plan for a function-local type as a
  generic type ARGUMENT where the rendered name is unobservable»); C6
  kept for TYPE instantiations, with a fresh pin.
* [AGENT] no-record rendering is a visible marker, not the key (§3.2)
  — the charter's fail-noisy rule over hand-built-test convenience.
* [AGENT] BUG-098 guarded whole-export rather than fixed (§2.5): the
  fix is frontend-wide in a file two parallel lanes are editing; a
  refusal by name is the charter's fail-closed posture; rowed FR-31.
* Not decided here (no hard stop reached): nothing in gc's display
  turned out layout-bound; `decl.gen` is compiler-internal and stays
  behind C6, as already ratified.
