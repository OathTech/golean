## What was asked (rule 6 — conclusion first)

gc realizes TWO `runtime.Error` texts when a VALUE-receiver method is
dispatched through an interface holding a nil `*T`, decided by its
optimizer on ONE source: the devirtualized call dereferences in `T.M`'s
receiver copy (`runtime error: invalid memory address or nil pointer
dereference`); the autogenerated `(*T).M` wrapper's nil check calls
`runtime.panicwrap` (`value method <pkg>.<T>.<M> called using nil *<T>
pointer`, a `plainError` without the "runtime error: " prefix). The
machine now admits BOTH as a width-2 demonic choice
(`ChoiceSite.nilValueMethodText`), exactly on gc's wrapper family.
The probes below settle the three questions the implementation had to
answer: the family's SHAPE (which programs), the QUALIFIER in member 1,
and the RENDERING of a generic receiver.
