# Dossier E4 — targets-vs-RHS unordered panic order (pinned to OUR point)

G3 register item 3. Inventory §E4; BUG-032 round-4 amendment (b)
(docs/BUGS.md). Same class as E3 — this dossier records what is

Proposal only — batched for user ruling.

## 1. The latitude

Within phase 1 of a multi-target assignment, the order between the
TARGETS' operand evaluations and the RHS operands' evaluations is
spec-open (same §Order of evaluation residue as E3 — only
calls/receives/binary-logical are ordered). Observable as which panic
wins when both a target operand and an RHS operand panic. Machine:
targets then RHS (tgtOpK → rhsK, StepFn.lean:459–500).

## 2. Evidence

### SPEC

Same text as E3's dossier §2 (quoted there); additionally §Assignments
fixes only the two-PHASE discipline:

> "The assignment proceeds in two phases. First, the operands of index
> expressions and pointer indirections (including implicit pointer
> indirections in selectors) on the left and the expressions on the
> right are all evaluated in the usual order. Second, the assignments
> are carried out in left-to-right order."

"In the usual order" defers to §Order of evaluation — which orders
none of the operand evaluations here. Both realizations conform.

### GC probes (`docs/evidence/2026-08-15-dossier-e4/`, verbatim)

- `xs[ys[9]], b = zs[7], 2` → gc reports the RHS's panic (`[7] with
  length 3`); the machine's point reports the target's (`[9]`).
  Reproduces the BUG-032 amendment-(b) record.
- NEW DATUM: `b, xs[ys[9]] = zs[7], 2` (panicking target moved to
  second position) → gc reports the TARGET's panic (`[9]`). gc's
  targets-vs-RHS pick is POSITION-DEPENDENT — there is no simple
  "RHS first" rule; the realization is compiler-internal exactly as on
  E3's axis, hence equally unpinnable.

### Corpus / de-facto / XIMPL / ARCH

Identical posture to E3 (incorporated by reference): no de-facto
pressure on multi-panic selection; XIMPL/ARCH NOT-OBTAINED; the
containment fact (frontend hoists calls out of target operands, so the
divergence cannot escape panic selection into side effects) covers
this axis too. Note the RHS side MAY contain calls — but calls are
lexically ordered by the spec, so the residue is again only the
non-call operand evaluations.
